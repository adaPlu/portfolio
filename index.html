01 // Flagship system

Quiz Royale Showdown

A production-oriented multiplayer platform spanning native Android, web, persistent services, real-time rooms, billing, and deployment.

Public · Original full-stack application

Trivia built like a live service.

Quiz Royale is a real-time trivia battle royale with Quick Match, Tournament, and Practice modes; registered and guest identities; seasons; cosmetics; friends; leaderboards; virtual currency; and optional Google Play purchases.

KotlinJetpack ComposeReactTypeScriptNode.jsPostgreSQLRedisCloudflare WorkersDurable ObjectsWebSocketsRailwayGoogle Play Billing

Durable state

Railway, PostgreSQL, and Redis own accounts, progression, economy, social data, and rewards.

Live rooms

Cloudflare Durable Objects isolate server-authoritative WebSocket rooms close to players.

Cross-platform

Android and web clients share the same signed matchmaking and room protocol.

Trust boundaries

Clients never grant rewards, settle matches, or validate paid currency themselves.

Why this architecture

Separate what must persist from what must feel immediate.

Kotlin and Jetpack Compose provide a native Android experience with lifecycle-aware state and Google Play Billing. React, TypeScript, and Vite provide a responsive browser client. Node.js and TypeScript keep API contracts close to the clients, PostgreSQL provides transactional durability, and Redis coordinates cached or shared state.

The fast match loop lives separately in Cloudflare Workers and Durable Objects. That split lets the account and economy service favor durability while each game room favors low-latency WebSocket events and a single authoritative state machine.

Banking Support Ticket Classifier

An end-to-end NLP project that turns a banking support message into one of 77 ticket categories. Try the deployed model with a fictional message and get a prediction through a public AWS API.

Pythonscikit-learnTF-IDFLogistic regressionFastAPIAWS LambdaAPI GatewayS3

Why this stack

TF-IDF and logistic regression provide a fast, interpretable baseline for short support messages. Comparing single words, phrases, and regularization settings selected the strongest validation model. FastAPI serves predictions on AWS Lambda through API Gateway; a private S3 bucket stores the deployment package.

Engineering details
  • 88.35% validation accuracy and 0.8841 macro F1 across 77 categories.
  • 7,999 training examples and 2,000 validation examples after removing four duplicates; the test set remains untouched.
  • Compared word and phrase features plus regularization strengths before selecting C=10.
  • Dataset: PolyAI BANKING77 (CC BY 4.0). Educational demo; use fictional messages and expect occasional classification errors.

Private source · Original Android game

Loopline Courier

A logistics puzzle where each delivery route you draw becomes a repeating loop. Plan a closed trip from depot to package to destination and back, then synchronize multiple couriers on shared streets while avoiding collisions, timed trains, gates and switches. Every decision is about distance, timing and coordination.

KotlinJetpack ComposeAndroidInteger-tick simulationJSON levelsPython verificationRobolectricRevenueCat

Why this stack

The plain-Kotlin rules engine is independent of Android and Compose: every courier position is computed from an integer tick and a route array, keeping simulations reproducible. Jetpack Compose Canvas draws the neighborhood and couriers without sprite sheets. JSON levels and a Python reference solver make puzzle content data-driven and verifiable.

Engineering details
  • Deterministic simulation: courier position is route[tick % length], so playback is consistent instead of physics-driven.
  • Collision and hazard diagnostics: the engine checks two full least-common-multiple periods and identifies the exact tick, street and couriers involved in failures.
  • 15 verified levels: the Neighborhood progression introduces longer routes, multiple couriers, switches, gates and train crossings.
  • Automated verification: Python tooling verifies author solutions, route necessity, replay encoding, and repeated determinism checks.
  • Versioned replays and saves: solved paths are stored as route instructions, then rendered in the level select screen.
  • Offline-friendly: core gameplay needs no connection; earned tokens, cosmetic trails and vehicle options do not alter the puzzle rules.

Public · Original game

ClickDungeon

A deterministic turn-based dungeon crawler on a compact 5×5 board: twenty floors in acts, nine heroes across eight classes, branching talent trees, and a rule that every monster telegraphs its blow a turn before it lands.

Unity 6C#.NET 10NUnitDeterministic simulationWindows · Android · iOS

Why this stack

The rules are an engine-free C# library: the domain, content, simulation and application assemblies carry no UnityEngine reference, so the same source compiles into the game and into a headless NUnit project that runs the whole rule set in minutes. Unity supplies rendering and the Windows, Android and iOS players. Integer-only arithmetic and a seeded RNG keep runs reproducible, which is what makes an autoplay bot usable as a balance instrument rather than a demo.

Engineering details
  • Two contracts the whole design answers to: every blow is telegraphed one turn ahead, and nothing may differ based on what an unrevealed tile hides.
  • 112 talents and 40 skills across eight classes, each tree a fork between two mutually exclusive capstones — the build chooses which verbs it carries.
  • 1,031 tests gate every playtest build: 466 headless rule tests, 562 Unity EditMode, 3 PlayMode.
  • An autoplay bot plays all 16 class builds over hundreds of seeded runs; guard thresholds are set from the measured tables with explicit sigma margins rather than tuned until green.
  • Versioned save schema and rule set with migrations, so a run in progress survives a content change instead of being refused.

Robotic Treasure Hunt

ROSC++catkinmove_baseAMCLDWA plannerTFLogical Camera

Why this stack

ROS supplies interoperable navigation, localization, action, transform, and sensor primitives. move_base and the DWA local planner handle obstacle-aware motion, while AMCL estimates the robot pose.   • Identifier tracking suppresses duplicate reports; project received 85/100.
